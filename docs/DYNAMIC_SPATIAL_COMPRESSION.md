# 基于相机视场的动态空间压缩设计

## 1. 目标与范围

本文记录 E0/F0--F2 这条“历史相对当前 query”的动态裁剪路径。该模块已将原本固定
`0.5` 保留比例的“锚点 + 新颖性”压缩升级为由相机运动直接
决定裁剪位置与 token 数量的动态空间压缩。核心原则是：只压缩已经被 FOV 检索选中的
历史 KV，CPU 记忆库仍保存完整、未压缩的干净 KV。

当前第一版聚焦 MBench-A 实际出现的水平 yaw 旋转：根据历史相机和当前相机的有向旋转
角度，求两者水平视场的交集，只保留历史 latent 中仍可能出现在当前视角内的空间列。
左右横向平移作为第二阶段扩展；前进/后退暂不做几何裁剪，先回退到现有固定压缩。

本实现不增加连续数值型公开超参数。启用 dyKV 后默认从 `viewmats` 和相机内参 `Ks`
推导所有几何量；消融只使用注册好的有限 case 枚举，而不是重新暴露阈值和权重。

后续实现的 predecessor 路径没有替换本模块，而是作为三个独立 case 共存：检索仍参考
当前 query，但压缩参考候选块的前驱 chunk，并使用四档大小。其完整定义见
[`PREDECESSOR_INCREMENTAL_COMPRESSION.md`](PREDECESSOR_INCREMENTAL_COMPRESSION.md)。

## 2. MBench-A 目前有哪些运动

这里必须区分“数据规范允许的运动”和“当前官方任务清单中实际分配的 case”。统计基于：

- 数据规范：`MBench-A/dataset.yaml`，SHA-256
  `ad96ce9f609cfde162214c5e1e025196333a9be420a322385acc62814a24ec42`；
- 当前官方任务清单：`MBench-A/models/hy_worldplay/samples.jsonl`，SHA-256
  `c3989038ab73fdc3e1a7e37f5b339685635771f42395ba77bb5310bf306dfc67`。

### 2.1 当前实际分配

当前任务清单共有 547 个 case，全部是 25 秒水平 yaw 往返旋转：

| 运动 | case 数 | minWM 轨迹 | 最大偏离 | 与本方案的适配性 |
| --- | ---: | --- | ---: | --- |
| `left_then_right` | 273 | `j*49,l*49,n*1` | 向左 147° 后返回 | 很适合 |
| `right_then_left` | 274 | `l*49,j*49,n*1` | 向右 147° 后返回 | 很适合 |

547 个 case 的 subset 分布为：`environment` 227、`human` 120、`object` 100、
`causal` 100。两种动作在各 subset 中都有覆盖。

MBench 中的 left/right 在 camera-interaction 定义中表示 yaw 旋转，并非横向平移；现有
适配器也因此使用 `j/l`，而不是 `a/d`。每个 latent 步骤默认旋转 3°。25 秒条件对应
100 个 latent 位姿，共 99 次运动：前 49 步向外旋转、后 49 步反向旋转，最后补 1 步
静止，因此最大偏离为 `49 × 3° = 147°`，最终回到初始朝向。

### 2.2 数据规范允许、但当前清单未分配的运动

| 运动 | 当前 case 数 | 运动性质 | 与本方案的适配性 | 第一版处理 |
| --- | ---: | --- | --- | --- |
| `forward_then_backward` | 0 | 前后平移 | 暂不适合；可见区域依赖场景深度 | 回退到固定压缩 |
| `left_360` / `right_360` | 0 | 单向完整 yaw | 很适合，适合作为补充压力测试 | 动态裁剪 |
| `left_720` / `right_720` | 0 | 两周 yaw | 很适合，适合测试周期回访 | 动态裁剪 |
| `left_1080` / `right_1080` | 0 | 三周 yaw | 很适合，适合测试多次回访 | 动态裁剪 |
| `static` | 0 | 相机静止 | 适合作为正确性对照，不体现压缩收益 | 保留全部可见 token |

数据规范允许 10 秒和 25 秒两种长度，但当前 547 个任务全部是 25 秒。10 秒 case 只能
通过自定义任务清单补充，不能作为当前官方结果的一部分报告。

### 2.3 当前没有覆盖的运动

MBench-A 当前规范没有横向平移、上下平移、pitch 或复合运动。minWM 轨迹解析器虽然支持
`a/d` 横移、`u/dn` 上下移动和 `i/k` pitch，但这些只能用于补充实验，不能混入官方
MBench 分数。横向平移没有只依赖旋转角度的精确裁剪公式：同一平移量在不同深度上产生
不同视差，因此需要深度、代理平面或三维 FOV 探针。

## 3. 适合性结论

当前官方 MBench-A case 很适合验证第一版算法，原因如下：

1. 两种动作都是纯水平 yaw，旋转可由位姿矩阵稳定求出，不需要深度。
2. 路径先离开初始视角再返回，正好检验“不可见时少保留、重新重叠时恢复记忆”的行为。
3. 左右方向数量接近，可检查动态裁剪是否存在方向偏差。
4. 四个 subset 都有样本，可同时观察环境、人物、物体和因果一致性。

但它只能证明纯 yaw 往返场景有效，不能证明横向平移、前后移动或复合相机运动有效。
尤其是当前清单没有 360°/720°/1080° case，因此完整旋转必须另建补充清单测试。

## 4. 已实现算法：yaw 视场交集裁剪

### 4.1 输入

对每个已被 FOV 检索选中的历史块，动态压缩接收：

- 每个历史 latent 帧的 `viewmat` 和 `K`；
- 当前 query 块 4 个 latent 帧的 `viewmat` 和 `K`；
- 当前层 K/V，形状为 `[B, T×H×W, heads, dim]`；
- 从实际 `grid_sizes` 获得的 `H×W`，不得硬编码 30×52。

`MemoryBlock` 已保存 `viewmats`、`Ks` 与从模型 patch size 推导的实际 latent 空间网格。
相机内参直接给出每一列中心射线的水平角度与左右边界。实现不硬编码 30×52；若 `K` 或
空间网格缺失，则回退到固定新颖性压缩并记录回退模式。

### 4.2 有向视场交集

设历史帧 yaw 为 `ψ_h`，当前帧 yaw 为 `ψ_c`，水平 FOV 为 `φ_h`。先将相对旋转
`Δψ = wrap(ψ_c - ψ_h)` 归一化到 `(-π, π]`。在历史相机的局部角坐标中：

```text
历史可见区间 I_h = [-φ_h/2, φ_h/2]
当前可见区间 I_c = [Δψ-φ_h/2, Δψ+φ_h/2]
交集              I = I_h ∩ I_c
角度保留比例       ρ = length(I) / φ_h
```

因此对称内参、纯 yaw 下有 `ρ = clamp(1 - |Δψ| / φ_h, 0, 1)`。实际实现没有用该比例
随机选择 token，而是根据针孔相机模型计算每个 latent 列中心射线的角度，再判断该射线
是否落入交集：旋转方向决定保留左侧还是右侧，列数由实际相机内参与视场交集共同决定。

对于当前 query 的 4 个位姿，分别计算历史帧的可见列 mask，再取并集。这样只要一个当前
query 帧能看到某个历史区域，该区域就会被保留。角度计算必须使用圆周区间，正确处理
跨越 ±180° 以及 360° 多周旋转后的等价朝向。

### 4.3 token 裁剪

1. 将每个历史帧的 token 恢复为 `[H, W]` 的行优先空间索引。
2. 根据有向视场交集生成长度为 `W` 的列 mask，并扩展到全部 `H` 行。
3. 使用同一组索引 gather K 和 V，索引保持原始行优先顺序。
4. 四个历史帧可拥有不同保留数量；记录逐帧 token 数和块总 token 数。
5. 若一个块对当前 4 帧 query 完全不可见，则该块不进入注意力，不用无关 token 填满预算。

K 已经包含空间 RoPE，按索引 gather 不会破坏保留 token 的空间位置编码。现有三区域时序
RoPE 仍按历史块整体平移时间原点，`4 + 8 + 8` 布局无需改变。

### 4.4 与现有压缩的关系

E0/F0--F2 当前实现直接用几何可见 mask 替代固定 `0.5` 新颖性裁剪，不叠加第二次裁剪。
原因是先单独
验证“裁掉当前视角不可见区域”是否正确，避免同时引入几何 mask 和相似度排序两个变量。

- 无相对 yaw：保留全部空间 token；
- 部分重叠：只保留对应方向和比例的空间列；
- 无水平视场重叠：丢弃该历史块的注意力载荷；
- 前后移动、位姿缺失或无法可靠分解 yaw：回退到当前“锚点 + 新颖性”固定压缩。

第二版再评估是否只在可见区域内部应用新颖性裁剪，以进一步减少 token。

## 5. 横向平移扩展

横向平移不能仅凭位移量得到精确像素对应。建议在 yaw 版本稳定后采用现有确定性 FOV
探针扩展：把同时落入历史和当前视锥的三维探针投影回历史图像，将被覆盖的 latent 网格
单元组成可见 mask。该方法能处理横向平移和旋转组合，但仍受探针半径及场景深度代理影响。

在实现横移前，先增加 `a_then_d`、`d_then_a` 自定义轨迹做补充测试。因为 MBench 官方
action schema 不包含这两类运动，它们只报告为补充实验，不计入官方聚合分数。前后移动
继续维持回退策略，直到引入可靠深度信息。

## 7. 主要风险

- 当前 MBench 只覆盖 yaw 往返，结果不能外推到平移或任意六自由度运动。
- 角度比例描述的是视场角域，不严格等于透视图像中的像素面积；第一版应同时记录角域
  比例与实际 token 保留比例。
- 只按旋转判断可见性会忽略动态物体、遮挡和场景深度，因此它是几何先验，不是真实可见性
  的完备估计。
- 在闭环返回时相对 yaw 接近 0，算法会保留较多历史 token；这是恢复旧视角所需的预期
  行为，不能简单视为压缩失败。
- 动态长度可能影响 FlashAttention 的吞吐，必须同时测量 token 减少量和实际耗时，不能
  只按理论 FLOPs 判断收益。
